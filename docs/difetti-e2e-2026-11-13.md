# Difetti del test end-to-end del 13/11/2026

Elenco dei difetti trovati nel test end-to-end manuale di tutta l'app (web su
backend Docker locale + app Android su emulatore), con quello che serve per
correggerli anche senza la conversazione in cui sono stati trovati.

Lo **stato** di ogni difetto è aggiornato man mano che vengono corretti
(☐ da fare, ☑ corretto, con il commit).

## Prima di mettere mano al codice

- **Due backend, una logica.** La web app usa il backend Java (`backend/`, Spring
  Boot, Postgres); l'app Android ha la stessa logica riscritta in TypeScript
  (`frontend/src/local/`, SQLite con sql.js). Una correzione alla logica va fatta
  **in entrambi**, con i test: Java in `backend/src/test`, TypeScript con un test
  in `frontend/src/local/parity/` (gli scenari dei test Java contro il backend
  locale). L'interfaccia (`frontend/src/pages`, `components`) è una sola.
- **Ogni test nuovo va visto fallire** sul codice vecchio (mutazione) prima di
  considerarlo valido. Un comportamento sbagliato che non si corregge si documenta,
  non si cambia in silenzio.
- **Produzione intoccabile.** Si prova solo in locale: `docker compose up -d
  --build` dalla radice (Postgres `spesometro/spesometro` su `db:5432`), account
  usa-e-getta creati via API e cancellati alla fine, login iniettando il JWT in
  `localStorage` (mai password nei form).
- **Commit** in italiano, con in fondo
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`; push su `develop`
  (Render pubblica il backend da `develop`, Vercel il frontend).
- **Suite:** `cd frontend && npx vitest run`, `npx tsc -b`, `npm run lint`,
  `npm run build` (la build web non deve contenere codice di `src/local`);
  backend `.\mvnw.cmd test` con `JAVA_TOOL_OPTIONS=-Djdk.net.unixdomain.tmpdir=<cartella con percorso lungo>`
  (il percorso temporaneo abbreviato di Windows rompe Java 21).
- **Android:** `frontend\scripts\build-apk.ps1` (debug) o `-Release` (serve
  `android/keystore.properties`, di Andrea); pubblicare un aggiornamento:
  `frontend\scripts\publish-apk.ps1` (release GitHub `android-v<numero>`). Sul PC
  l'emulatore affidabile è l'AVD **Pixel_10** con
  `-gpu swiftshader_indirect -memory 4096`; la WebView si guida via CDP
  (`adb forward tcp:9222 localabstract:webview_devtools_remote_<pid>`), i file
  binari si tirano fuori con `adb exec-out run-as it.mysimpleeconomy.locale cat …`.
  Guida completa: `frontend/ANDROID.md`.

## Gravi

### D12 — Sul telefono le categorie archiviate non si possono ripristinare ☐
- **Dove:** `frontend/src/pages/CategoriesPage.tsx` (pannello "Categorie
  archiviate" solo `!isMobile`, riga ~383; il commento dice che è voluto).
- **Passi:** layout mobile (l'app Android lo è sempre) → apri una categoria →
  Archivia. Sparisce e non c'è nessun punto da cui riattivarla.
- **Atteso:** le archiviate raggiungibili anche su mobile, con Riattiva ed Elimina.
- **Correzione proposta:** una sezione "Categorie archiviate" anche nel layout
  mobile (stessa logica del desktop: `archivedQuery`, conferma di riattivazione).

### D15 — "Elimina nel periodo" cancella subito, senza conferma ☐
- **Dove:** `frontend/src/pages/SettingsPage.tsx`, `handleRangeDelete`.
- **Passi:** Impostazioni → Transazioni → date → "Elimina nel periodo": cancella
  subito (nel test 13 transazioni e un saldo). "Elimina tutto" invece chiede di
  scrivere ELIMINA.
- **Atteso:** una conferma che dica cosa sta per sparire (periodo, e possibilmente
  quante transazioni) prima di cancellare. Sul telefono non c'è un server da cui
  recuperare.

### D14 — App Android, tema scuro: barra di stato e di navigazione restano bianche ☐
- **Dove:** `frontend/src/local/statusBar.ts`, `frontend/src/components/ThemeColorSync.tsx`,
  `frontend/capacitor.config.ts` (`adjustMarginsForEdgeToEdge: 'auto'`).
- **Passi:** app sul telefono → Impostazioni → tema scuro. La fascia della barra di
  stato in alto e quella dei gesti in basso restano chiare (#F8F8F8 circa),
  `dumpsys window` mostra ancora `LIGHT_STATUS_BARS`; l'ora quasi non si legge.
- **Atteso:** fasce del colore dello sfondo dell'app e icone chiare sul tema scuro.
- **Note:** con i margini edge-to-edge di Capacitor le fasce sono lo sfondo della
  finestra, non la barra: `StatusBar.setBackgroundColor` non basta. Da verificare
  anche perché il flag "light" non cambia (ordine delle chiamate / ripetizione su
  ogni cambio tema).

## Minori

### D4 — Debito creato oggi con "già pagato": la rata registrata oggi non conta ☐
- **Dove:** `backend/.../service/DebtService.java` (filtro `occurredOn.isAfter(alreadyPaidAsOf)`),
  `frontend/src/local/services/debts.ts` (`paidFromTransactions`), form `DebtForm.tsx`.
- **Passi:** nuovo debito con "già pagato 200" (la data è oggi, il form non la
  chiede) → registra oggi una spesa nella categoria del debito → il residuo non cambia.
- **Atteso:** la spesa registrata dopo aver creato il debito conta. Stesso problema
  già risolto per i saldi con `counts_from` (istante di creazione): le transazioni
  del giorno di `alreadyPaidAsOf` contano se create dopo il debito.

### D5 — Dashboard, "Prossime scadenze ricorrenti" ignora le eccezioni ☐
- **Dove:** `frontend/src/pages/DashboardPage.tsx` (lista `upcomingExpenses`).
- **Passi:** regola Netflix 9,99 con eccezione 12,99 sulla prossima scadenza → la
  card mostra 9,99; la previsione usa correttamente 12,99.
- **Atteso:** l'importo dell'eccezione per quella scadenza.

### D7 — Export, "Andamento del saldo": saldo iniziale 0 se il saldo registrato cade il primo giorno del periodo ☐
- **Dove:** `backend/.../service/ExcelExportService.java` (`balanceAt(start.minusDays(1))`),
  `frontend/src/local/services/excelExport.ts` (stesso calcolo).
- **Passi:** saldo 3000 al 27/08, stipendio il 27 → foglio "Andamento del saldo",
  riga di settembre: saldo iniziale 0, saldo finale 4013,61 (la riga non torna).
- **Atteso:** saldo iniziale 3000 (0 + 1800 − 786,39 ≠ 4013,61; 3000 + 1800 − 786,39 = 4013,61).

### D8 — Export, "Andamento del saldo": il saldo finale conta movimenti futuri che le colonne escludono ☐
- **Dove:** stessi file di D7.
- **Passi:** spesa futura (20/11) e export senza filtri (arriva fino a oggi) → riga
  di novembre: uscite senza la spesa futura, saldo finale con.
- **Atteso:** saldo finale coerente con le colonne della riga (fino alla data di fine export).

### D11 — Con il server che risponde 502/503 la spesa non va in coda offline ☐ (da verificare)
- **Dove:** `frontend/src/api/client.ts` (interceptor: solo `error.response === undefined`),
  `frontend/src/pages/TransactionsPage.tsx`, `OfflineSyncContext.tsx`.
- **Passi:** backend che risponde 502/503 (es. Render durante un deploy, o il proxy
  di Vite a backend spento) → nuova transazione → "Salvataggio non riuscito",
  niente coda.
- **Atteso:** 502/503/504 trattati come "server non raggiungibile": coda offline.

### D13 — Sul telefono il form dei promemoria parla di email ☐
- **Dove:** `frontend/src/components/ExpenseReminderForm.tsx`.
- **Testo:** "Se vuoto, non riceverai email per questo promemoria." In modalità locale
  sono notifiche Android: va detto "notifica".

### D2 — Import del diario: per una spesa si possono scegliere categorie di entrata ☐
- **Dove:** `frontend/src/components/ImportPanel.tsx` (selettore categoria delle righe).
- **Passi:** una riga del diario da categorizzare → il menu propone anche Stipendio,
  Bonus, Regali… Scegliendone una la spesa diventa un'entrata (il tipo viene dalla
  categoria alla conferma).
- **Atteso:** per le righe del diario (spese) solo categorie di uscita, tranne lo
  stipendio che è già risolto da sé.
